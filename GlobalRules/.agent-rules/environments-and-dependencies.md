# 虚拟环境与依赖卫生

## 触发

创建/激活运行环境，安装、升级、删除或声明依赖，运行依赖于特定解释器/工具链的命令。

1. 先读取项目依赖声明、锁文件、工具配置和文档，识别既有包管理/隔离方案；优先复用项目已有环境，不凭终端提示符假定仍处于激活状态。
2. 不把项目依赖安装到系统级或用户全局环境，不擅自修改 PATH、全局配置、系统包、服务或默认解释器。
3. Python 项目优先复用项目既有 uv/Poetry/PDM/Conda/venv。没有方案且任务确需安装时，在项目根创建项目级 `.venv`（项目已有命名约定则沿用），并通过其明确解释器路径运行安装、测试和脚本。
4. 创建 `.venv` 前检查目标不存在或确属当前项目；不覆盖来源不明环境。Git 项目按 workspace-and-version-control.md 核对 `.gitignore`，确保环境目录不进入版本控制。
5. Node、Java、Rust、Go、Ruby、PHP、.NET 等沿用现有包管理器、锁文件和项目级缓存/工具入口；不无理由引入第二套生态。
6. 新增持续运行/开发依赖时同步更新正确的声明、锁文件和必要说明；不能只在当前机器安装。一次性分析/转换工具尽量使用受控临时或宿主环境，不擅自加入生产依赖。
7. 安装前核对包名、来源、版本约束和目标环境；安装后核对实际解释器/工具版本、依赖解析结果及必要构建/测试。
8. 依赖变更超出计划、可能影响部署/许可/安全或需要联网外发信息时，先遵守项目审批和外部动作规则。
