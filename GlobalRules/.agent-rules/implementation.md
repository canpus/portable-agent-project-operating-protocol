# 代码与软件配置实现

## 触发

创建、修改、调试或评审代码、脚本、应用配置、接口、构建逻辑。

1. 先读取目标入口、调用关系、接口、数据结构、依赖声明、相邻实现和现有测试；源码与运行证据优先于旧说明，不无目的扫描整个仓库。
2. 沿用项目语言版本、目录结构、命名、格式化、类型、错误处理、日志和测试惯例。没有惯例时选择清晰、直接、可维护的最小实现。
3. 每个修改围绕一个可解释目标；不因架构审美顺手重构，不预先实现没有真实需求的扩展点，不静默改变公开接口或数据格式。
4. 明确输入、输出、副作用、错误行为和兼容边界；验证外部/不可信输入，不静默吞异常。日志保留定位所需上下文，但不记录秘密或无必要业务数据。
5. 注释解释原因、约束和非显然取舍，不逐行翻译代码；删除或更新因本次修改而失真的注释，不伪造 TODO 已完成。
6. 优先复用现有库、脚本和抽象；新增依赖先按 environments-and-dependencies.md。一次性脚本不强制建立完整服务日志、轮转和关联 ID。
7. 调试先复现或取得原始错误，缩小问题范围，基于证据修复原因；不能稳定复现时说明限制，使用针对性检查，不虚构根因。
8. 修改后运行与风险相称的受影响测试/静态检查，检查 diff 和重要失败路径；启动、编译或单个测试成功不能自动证明目标功能正确。
