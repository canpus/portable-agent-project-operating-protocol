# 工作区、文件、.git 与 .gitignore

## 触发

创建、修改、覆盖、移动或删除持久文件；使用版本控制；修改 `.gitignore` 或其他忽略配置。

1. 确认工作区和真实项目根。检测 `.git` 时同时考虑目录和 worktree 的 `.git` 文件，用版本控制命令核对根、分支/修订和相关状态；不假设当前目录就是仓库根。
2. 不直接编辑、复制、移动或删除 `.git` 内部数据；不把另一个仓库的 `.git` 带入交付物。需要隔离工作区/分支时遵守宿主和用户授权。
3. 修改受版本控制文本前检查相关状态与 diff，在用户已有改动上做局部编辑。发现无关改动保持原样，不运行会改写大量文件的全项目格式化/自动修复。
4. 二进制、未跟踪、非版本控制或不可可靠 diff 的原件，使用副本、备份、元数据、哈希、结构或格式对应检查保护；看不到文本 diff 不代表可覆盖。
5. 读取现有 `.gitignore` 后再修改：保留原顺序和语义，只追加当前项目确需忽略的生成物；不覆盖文件，不写宽泛规则隐藏源码或用户改动，不以忽略代替清理/归属判断。
6. 当前任务创建项目级虚拟环境时，若仓库未覆盖对应路径，在 `.gitignore` 最小追加准确条目（常见为 `.venv/`）；若项目已有约定则沿用。非 Git 项目不为形式创建 `.gitignore`。
7. 写入后检查实际路径、相关 diff、格式/结构和是否误包含生成物、秘密或原件。不要为了“整洁”移动 canonical 源码、配置、文档或交付物。
8. 未经用户明确要求，不执行 commit、push、merge、rebase、tag、强制推送或历史改写。禁止硬重置整个工作区、强制清理未跟踪文件和未核实目标的递归删除。
9. 撤销只撤销能确认由当前任务产生的内容；目标有不明并发变化时停止覆盖，重新读取并合并，无法判定归属则报告冲突。
