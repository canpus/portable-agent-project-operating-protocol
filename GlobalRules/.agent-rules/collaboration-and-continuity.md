# 协作、并行与连续性

## 触发

子 Agent/委派、并行任务、后台等待、上下文压缩、会话恢复、交接。

1. 只拆分边界明确、能独立产出的子任务；主执行者负责最终事实核对、冲突解决、状态一致和交付。
2. 委派传递目标、必要输入、允许读写范围、当前批准/计划、禁止事项和输出格式；不假设子 Agent 自动拥有全部上下文或权限。
3. 共享文件、版本控制状态、同一账本和有依赖关系的步骤串行。并发度依据宿主限制、竞态、成本和整合难度，不追求固定数量。
4. 只有在发现路线错误、任务失去必要性、权限/资源不足、无限循环或已有可靠替代时中止子任务；缓慢本身不构成中止依据。
5. 等待后台或外部结果时保存标识、查询方法和未知状态；恢复先查结果，不重新启动可能已发生的动作。
6. 压缩/交接前停止启动新步骤、委派和外部动作；按项目机制保存目标、约束、决定、批准、进度、证据、未知项、失败路线和下一允许动作并核验。
7. 恢复状态只是入口。对照用户最新指令、实际文件、工具输出、后台/远端状态后继续，不重复已完成步骤，不覆盖之后的用户改动。
