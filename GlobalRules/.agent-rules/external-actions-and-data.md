# 外部动作、数据与凭据

## 触发

第三方外发、消息发送、公开发布、购买、生产环境、账号/权限、系统/全局环境、重要删除、远端覆盖、历史改写，以及使用真实凭据。

1. 执行前明确对象、动作、数据、成本和影响范围，检查用户对该具体范围的授权及项目审批关卡。计划中提到动作不等于动作已获授权。
2. 缺授权时先完成允许的草稿、补丁、预览和本地验证，再提出一个可审阅的明确问题；不发送、不购买、不部署、不发布。
3. 已有具体授权且对象/范围未变时不重复询问；新接收者、数据类别、费用、环境或破坏性影响需要重新判断。
4. 用户把材料交给当前宿主不表示授权再次发给第三方。源码、业务数据、日志、文档、个人信息、图像音视频和凭据只外发完成目标所必需的最小范围。
5. 凭据使用宿主/环境的最小暴露机制；不主动查找无关秘密，不把真实秘密写入文件、输出、补丁、日志、测试快照或提交。模板只用明显占位符。
6. 结果可能因超时/中断不确定时，执行前保存对象、动作、授权依据、查询方法和可用幂等标识；执行后核对远端状态/收据。未知先查询，不盲目重试。
7. 破坏性操作即使已授权也要核对精确目标、通配符、变量和边界；执行后说明实际影响及能否恢复。
8. 宿主真实审批不能绕过；自动审批拒绝时寻找更安全替代，仍阻塞则说明动作、原因和所需授权。
