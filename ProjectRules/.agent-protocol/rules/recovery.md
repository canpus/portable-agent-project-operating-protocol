# 恢复与冲突处理

1. 运行只读 `verify`，再检查项目文件、版本控制 diff、产物和测试；状态是恢复入口，不是不可质疑的事实。
2. 存在事务文件时，用同一 next-state 重跑 commit；脚本按 Current/Snapshot/History 已完成程度幂等补齐。
3. 发现锁时检查进程/事务与三个生成账本。无法证明锁陈旧就停止，不抢占。
4. Append-only 账本损坏时保留原件，报告首个不一致位置；不得补造用户决定或静默改写历史。
5. 新 Session 先读取三层 Case index、Current 全文和最近 History；再按关键词定点跟随 Ref，不全量加载 Snapshot。
6. 账本与真实工作区冲突时，以用户最新指令和实际文件/diff 为证据，追加纠正记录，不伪造过去已正确。
