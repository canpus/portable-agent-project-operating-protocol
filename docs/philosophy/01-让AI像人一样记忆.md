# 让 AI 像人一样记忆

> **PAPOP Design Philosophy #001**

---

**我越来越怀疑，大家聊“AI 长期记忆”的时候，很多讨论一开始就跑偏了。**

上下文从 100K 拉到 500K，再拉到 1M，听起来当然很爽。

窗口越大，模型能看到的历史越多，于是很容易产生一种错觉：它记住的东西也越来越多。

可我真拿 AI 去做一个持续很久的项目之后，感受完全不一样：

项目越往后走，AI 背着的东西越多，旧需求、新需求、已经作废的方案、当时随口讨论过的想法、真正已经定下来的决定，全堆在一起。

它当然“看得到”，可它未必还分得清哪些东西今天依然有效。说白了，这跟记忆力强没多大关系，更像背包越来越重。

## Context 更像工作台

我现在更愿意把 Context 当成一张工作台。

桌子大一点挺好的，谁都喜欢大桌子。

可桌子再大，你也不会把公司所有历史档案、三年前的会议记录、已经废掉的方案、几十次失败尝试一起摊开放在桌面上吧？

真这么干，桌子最后只会变成垃圾场。AI 的超长上下文很多时候也有这个味道。

长期项目真正麻烦的地方，从来都不只在“过去的信息还在不在”。更麻烦的是：**什么还算数，什么已经作废，为什么当初这么决定，现在到底做到哪一步，接下来该干什么。**

上下文可以把东西装进去，却不会自动替你把这些关系理清楚。

## 人类自己其实就他妈的记不住多少东西

今天开完会，过两天就有人问“这个需求当时谁提的”；

一个月以后，大家开始互相确认“这个逻辑还能不能改”；

半年以后，看到一坨奇怪代码，所有人都沉默，因为谁也不知道当年为什么这么写。

我们天天吐槽“屎山”，很多时候真正让人不敢动手的，代码复杂只占一部分。更要命的是上下文死了，决策历史没了，写这些代码的人离职了、换人了，没人敢确定删掉以后会不会把某个早就忘掉的业务逻辑一起送走。

所以人类搞出了需求文档、项目计划、Git、Issue、会议纪要、决策记录、版本号、Checkpoint、Runbook。

仔细想想，这些东西的存在本身就挺打脸的：

> **我们根本没把希望寄托在人脑上，这玩意儿好像一直都不怎么靠谱。**
>
> **成熟项目能长期跑下去，靠的是把重要信息放到脑子外面，而且还得分门别类，不然压根找不着。**

## 那如果把这个思路套给 AI Agent 呢？

PAPOP 最早其实没这么复杂。那时候我只是想让 AI 帮我做个自动报关文件生成工具。

我连程序员都算不上——如果你觉得一个三年前自学了两周 Python 的文科生也能算程序员的话，那你赢。说“编程小白”反而更准确，所以我只能依靠 Agent，给它提出一个初始需求，再不断地提新的需求，然后双手合十，祈祷它能变出我想要的东西。

结果项目越做越长，上下文越来越肥，我开始担心压缩以后模型把前面的东西忘掉，于是先让它记 History。

History 长了，2000 多行，每次全量读实在太烧 token，于是又搞 Current State，再给 History 加结构和索引，让它先看自己现在在哪，真需要历史的时候再回去捞。

然后我发现 AI 有点太奔放了，它想咋干就咋干，我得知道它想干啥吧？于是有了 Plan。

后来我发现“做了什么”还不够，**为什么这么做更重要**，于是 Decision 也出来了。

再往后，关键变化到底有没有经过我确认，也得管，于是又长出了 Approval、Revision、Checkpoint、Recovery……

老实说，等我回头一看，我自己都觉得有点离谱。

因为不想让 AI 在长期项目里失忆，我最后居然折腾出了一套这么复杂的东西。

## 我靠，这他妈的是个什么玩意儿？

当我把项目仓库地址发给 GPT，让它给我画个流程图——顺带一提，我当时都不知道怎么给别人解释这个玩意儿，所以才让 GPT 画个流程图——我自己都有点懵。

**我靠，这他妈的是个什么玩意儿？**

**这他妈的是我搞出来的玩意儿？**

### 那我是不是可以叉会儿腰了？

叉腰归叉腰，我心里其实一直有点虚：这套思路是不是早就有人做过？有没有人已经做得比我成熟十倍？我不知道。

毕竟我真的是一路遇到问题、想办法解决问题、再遇到新的问题，就这么过来的。

我甚至连“状态机”这个词都不知道。v0.1.0 第一次推到 GitHub 的时候，我连仓库名字都懒得自己想，直接让 DeepSeek 帮我取。它给我起了个带 `protocol` 的名字。后来继续讨论架构，我才慢慢意识到：**哦，原来我这玩意儿里面已经长出状态机那一套东西了？**

后来，越来越多的人跟我聊 Agent 长任务的时候，开始问出和我当初差不多的问题。到这里我才慢慢有了点底气：至少这个坑不是我一个人踩到的。

**PAPOP 到底是不是个好答案，我还在验证。但这个问题，我现在基本敢确定：它真他妈存在。**

说真的，现在想想，我好像只是一次次撞墙，然后发现每次撞墙背后都指向同一个东西——**模型的会话上下文承担了太多它本来就不该长期承担的责任。**

每次撞墙，我都只是想解决眼前的问题，然后一步步下来，它居然慢慢变成了这样。

## 让重要的信息有自己的位置

后来，我不再纠结“怎么让 AI 永远别忘”，这个目标怎么听怎么不靠谱。

我开始觉得，真正重要的，是**让项目里的关键信息有自己的位置**。

- **Goal**：放目标；
- **Plan**：管下一步；
- **Decision**：记为什么；
- **History**：记发生过什么；
- **Current State**：说现在在哪；
- **Approval**：记录哪些关键变化真的确认过。

模型每次回来，不需要重新背诵整个项目，只要先搞清楚当前状态，再按需去找过去的信息。

这样一来，AI 甚至可以大胆忘。只要账本还在，它就不至于因为一次压缩、一次断线或者换个 Session，突然把整个项目忘个干净。

当然，你要是手欠把账本一起扬了，或者在 AI 记账之前就压缩了，那当我没说。

它不需要死死抱着 500K 上下文，生怕压缩一下整个项目就断片。项目状态在外面，历史也在外面，真正需要的时候再去读。

> **今天的工作台上只需要摆今天要用的东西，其他的东西就安安静静待在仓库里。**

这跟现在很多“让模型记住更多”的思路好像有点拧着来。我也不确定我最后会不会证明自己想对了，毕竟我一路上踩过的坑不少，PAPOP 现在也远远谈不上成熟。

但我越来越觉得，一个长期 Agent 真正值得追求的能力，可以浓缩成一句话：

# **就算忘了，也不会把项目弄丢。**

我不太想要一个靠记忆力硬扛全场的“天才型 Agent”。

我更想要一个靠谱的**项目搭子**：脑子里不用装下所有东西，可他知道项目现在在哪，知道什么决定已经定过，知道该去哪查历史，知道什么时候该停下来确认，也知道中断之后怎么回来继续。

如果最后 PAPOP 真能走通，我觉得它最有意思的地方也许就在这里。

## 我知道自己很菜，但菜鸡也是有脑子的

这篇文章我不打算装得多权威。我知道自己几斤几两：一个三年前自学过两周 Python、靠 Agent 写代码的纯菜鸡，菜得不能再菜。

可我也不准备因为自己是菜鸡，就假装没看到已经撞上的问题。

**菜鸡也是有脑子的好吧？**

我现在能确定的只有一件事：

> # **真正重要的项目状态，最好别只活在模型的脑子里。**

至于这条路最后能走多远，我还在继续试。
