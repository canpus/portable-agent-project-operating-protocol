# v4 安装、验证与日常使用

## 先选择治理方式

| 包 | 全局规则 | 项目入口 | 审批 | 记录 |
|---|---|---|---|---|
| GlobalRules Only | 有 | 无 | 由宿主、用户和项目原规则决定 | 不创建 PAPOP 状态机记录 |
| 计划审批 | 有 | PLAN_APPROVAL | 确认需求、批准精确计划、人工验收 | 实际任务 TRACKED |
| 任务委托 | 有 | TASK_DELEGATION | 缺关键决定/具体授权或用户关卡时等待 | 默认 AUTO |

计划审批控制的是计划和阶段。获批计划内步骤可连续执行，范围内返工无需新计划。需要每步批准时明确指定步骤关卡。

## 安装 GlobalRules

把 ZIP 内 GlobalRules/AGENTS.md 内容放进宿主支持的全局规则机制。不同宿主的加载位置和限制不同，按其实际规则机制处理，不只把文件放到看似合理的位置。

已有全局规则先备份、合并，不覆盖组织或宿主要求。GlobalRules 不要求你创建任何项目账本，也不授予文件、网络和账号权限。

## 安装项目规则

仅两个状态机包需要此步骤。把 ProjectRules 内 AGENTS.md 和整个隐藏目录 .agent-protocol 放进目标项目根。不要把源码或交付物搬进状态目录，不要安装仓库中的 AGENTS.template.md。

已有项目入口先备份并合并，保留构建/测试、保护目录和业务约束。移除旧状态机加载指针；旧文件和账本可归档保留，但不能继续作为第二套执行入口。

确认安装后的配置：

```text
计划审批包：
PROTOCOL_VERSION: 4.0.1
GOVERNANCE_MODE: PLAN_APPROVAL
RECORD_MODE: TRACKED

任务委托包：
PROTOCOL_VERSION: 4.0.1
GOVERNANCE_MODE: TASK_DELEGATION
RECORD_MODE: AUTO
```

配置是入口中的明确文本，不是需要安装的程序。任务委托可由维护者改为 TRACKED；计划审批不能配成 AUTO。变更活动任务模式按 MIGRATION.md。

## 只读检查是否加载

在新会话中说：

> 实际检查当前已加载规则及来源。说明治理模式、记录模式、哪些动作必须等待、哪些能继续；列出当前入口引用的规则及模板是否存在。暂时不要创建任务记录、修改文件或开始施工。

正确表现：能指出真实来源；区分审批与记录；只加载当前模式；两个状态机包能够找到 SCHEMA、十份详细规则和六个模板；安装检查本身不建账。GlobalRules Only 不应因为检查就创建项目状态机。

如果仅能口头复述，不能证明规则已经影响实际执行。接着在可丢弃的测试项目运行 BEHAVIOR_CHECKS.md 的典型场景。

## 计划审批的一个完整循环

1. 提出实际目标。Agent 只做允许的调查并提交需求理解，等待你确认。
2. 确认需求理解后，Agent 写入自包含提案并给出精确 PLAN_REF。确认理解不等于计划批准。
3. “批准这个计划，按这个范围执行。”上下文唯一时无需手输 ID；Agent 记录真实 PLAN_APPROVED，绑定该修订后执行。
4. 执行完成，Agent 给出 DELIVERY_REF、路径/指纹、实际验证与未验证项，保持待人工验收。此时 Agent 侧可以 COMPLETE，但任务不能 DONE。
5. “验收通过，接受这份交付。”Agent 记录 DELIVERY_ACCEPTED，绑定该候选，保存完成状态。

拒绝计划会形成新提案；实质范围变化重新确认并审批。范围内交付返工沿用有效批准，但新候选重新验收。沉默不批准也不验收。

## 任务委托的一个完整循环

1. 提出明确目标、范围和约束。普通任务内步骤直接执行。
2. 小任务满足 FAST 的全部条件可不建账；出现正式计划、需恢复的中间成果、等待、用户关卡等立即 TRACKED。
3. 每个正式计划步骤验收完成后保存检查点并继续已授权工作。
4. 缺少关键决定或高影响动作具体授权时等待相关动作，完成其他允许工作。
5. 未要求人工验收时可完成 Agent 侧工作并关闭，ACCEPTANCE_STATUS: NOT_REQUIRED；不能说用户已接受。

你可以说“先审计划”“第二步前等我”“我验收后再关闭”。这些关卡必须记录，不能由模型认为风险低而跳过，也不会自动切换整个项目模式。

## 准备压缩与恢复

保存请求：

> 保存并核验 PRE_COMPACTION，保留当前治理、活动/待批计划、人类决定与关卡、交付验收、成果证据、未知动作、失败路线及下一允许动作。保存后暂停，给出 current_state 路径。

恢复请求：

> 读取 `<current_state 路径>`，按 recovery.md 核对最后事件、计划、决定及实际依赖后继续，不重新开始，不越过已有等待关卡。

保存要有真实文件和读回核验。失败先修复，不急着压缩。恢复待批计划仍待批，待验收仍待验收。未知外部结果先查询，不能重发。

## 常见问题

**为什么没有 .agent-work？** GlobalRules Only 无状态机；任务委托的 FAST 不建账；纯讨论两种模式均不建账。

**为什么批准计划后还要问发布？** 计划批准与具体外部授权不同，特别是计划排除项、用户另设关卡或对象/数据/成本尚不明确时。

**为什么每一步都问？** 先让 Agent 指出具体规则：用户步骤关卡、计划尚待批准、旧入口仍加载，或宿主真实审批。普通步骤检查点不新增批准要求。

**保存成功是否表示已批准？** 不是。写入和核验检查点证明状态保存，不替人类作决定。

**能同时用两种模式吗？** 同一项目入口只能选择一个模式，同一任务账本只能有一个写入者。不同项目可选择不同模式；项目内活动任务配置冲突必须先处理。

**需要安装维护者脚本吗？** 不需要。Agent 运行协议只需要 Markdown；scripts/tests 只供仓库构建和验证使用。
