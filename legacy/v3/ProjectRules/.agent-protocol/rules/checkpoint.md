# 检查点、历史与压缩前落盘

## 触发

- 正式计划创建或修订已经写入；
- 计划步骤完成，或出现需保留的中间进展；
- 关键用户决定或授权变化；
- 外部动作执行前后的状态需要防重复；
- 任务完成、取消、等待、阻塞或交接；
- 用户要求“落盘、保存进度、准备压缩”。

## 记录职责

- `current_state.md`：完整、当前、可直接恢复；每次检查点全量更新。
- `history.md`：Schema 化的追加事件，只写本次变化和快照指针。
- `snapshots/<EVENT_ID>.md`：该检查点的完整 current_state 副本，创建后不回写。
- `plan.md`：只追加正式计划修订；步骤进度写在 current_state 和 history，不回写旧计划。

## EVENT_ID 分配

1. 从 current_state 取得 `LAST_EVENT_ID`，再用 `rg -n '^EVENT_ID:' history.md` 或等效搜索核对已有最大编号。
2. 检查目标快照文件是否存在。选择任务内下一个未使用的事件 ID：`E-` 加 6 位数字，例如 `E-000014`。
3. current_state、snapshot 与 history 必须使用同一个 EVENT_ID。发现同 ID 不同内容时停止冲突写入，进入 recovery.md 的修复流程。

## 保存事务

多文件写入不一定原子化，必须使用以下固定顺序并允许恢复：

1. **收集事实**：核对本次事件、当前计划步骤、实际文件、验证结果、未完成项、用户最新约束和未决外部动作。步骤未满足验收条件时不能记 STEP_COMPLETED。
2. **读取契约**：首次写入或字段不确定时，搜索 SCHEMA 中 current_state、history 和 snapshot 的相关章节；不要加载无关章节。
3. **生成下一状态**：在任务目录写 `current_state.next.md`。从上一状态继承仍有效的目标、约束、用户决定、已完成证据和失败路线；合并新事实，不对旧摘要反复缩写。
4. **校验下一状态**：检查必填字段、枚举、路径、PLAN_REF、ACTIVE_STEP、LAST_EVENT_ID 和下一步。读回关键段落，确认没有把 UNKNOWN 写成事实。
5. **保留上一状态**：当前 current_state 有效时，将它复制为 `current_state.prev.md`。不得让模型重新复述生成副本。
6. **更新当前状态**：用宿主支持的安全替换方式将 next 内容置为 current_state。无法原子替换时保留 prev，再写入并读回；不得宣称整个多文件事务是原子的。
7. **创建快照**：复制 current_state 为 `snapshots/<EVENT_ID>.md`。快照内容必须与当前状态一致，不重新生成。
8. **追加历史**：按 SCHEMA 在 history 末尾追加一个 `HISTORY_EVENT` 块。追加前精确搜索 EVENT_ID；已存在且一致则不重复，不一致则停止并修复。
9. **更新索引**：只有任务创建、激活、等待、阻塞、完成或取消时，向 task_index 追加对应事件并更新 active.md；普通步骤检查点不写项目索引。
10. **读回验收**：检查 current_state 的 LAST_EVENT_ID、快照内容、history 中唯一的 EVENT_ID、PLAN_REF、STEP_ID 和 NEXT 一致。全部成立才报告“检查点已保存”。

任一步失败时，说明最后成功的步骤和残留文件。先使用 recovery.md 修复一致性；未修复前不得声称状态已经安全落盘。

## 普通里程碑

保存成功后向用户简报：事件 ID、事件类型、完成的里程碑、current_state 路径和下一步。继续当前授权范围内的工作，不询问“是否继续”。

## 用户准备压缩

1. 立即停止启动新的计划步骤、委派和外部动作。已经运行的操作能安全收取结果时收取；不能时记录进程/任务标识、当前状态和恢复查询方法，不谎称已停止。
2. FAST 任务先升级 TRACKED，只记录已有真实事实；若此前没有正式计划，可写一个包含当前目标、已完成部分和下一步的首次计划，不补造历史。
3. 使用事件 `PRE_COMPACTION`，将 current_state 的 `RESUME_MODE` 设为 `READY_FOR_COMPACTION`。保留真实任务 STATUS；未完成任务不能标 DONE。
4. 状态必须包含：当前 PLAN_REF、步骤状态、关键约束与决定、已授权和待确认动作、已完成证据、未验证项、下一步验收条件、失败路线和未决外部动作。
5. 执行完整保存事务。成功后只报告 EVENT_ID、current_state 路径、下一步和未决事项，并给出恢复提示；然后等待用户，不自行压缩或继续新工作。

模型不检查上下文占用，也不估算 Token，不在规则中设定数值阈值。上下文占用及手动压缩动作由用户或宿主自行观察与处理。用户明确说“落盘后继续”时，以该要求为准。
