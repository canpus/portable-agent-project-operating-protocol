# 工作区、文件与版本控制

## 触发

创建、修改、覆盖、移动或删除持久文件；执行改变版本控制状态的操作。

1. 确认 PROJECT_ROOT、目标路径和任务范围。读取目标内容；受版本控制管理时检查相关状态与 diff，在现有修改上编辑。
2. 只修改完成任务所需的最小范围。不得覆盖、还原、删除或格式化无关用户改动；不得运行会改写大量无关文件的全项目自动修复。
3. 二进制、未跟踪、非版本控制或无法可靠 diff 的原件优先另存新版本。原始输入保持原位，派生结果与原件分开。
4. 不为配合任务账本移动源码、配置、文档或交付物。`.agent-work/` 只保存状态、计划、事件与快照。
5. 未经用户明确要求，不执行 commit、push、merge、rebase、tag、强制推送或历史改写。本地隔离分支/工作区只有在宿主和用户授权范围允许、且能保护现有工作时才使用。
6. 禁止硬重置整个工作区、强制清理未跟踪文件和未核实目标的递归删除。撤销只撤销能确认由当前任务产生的修改。
7. 目标文件有不明并发变化时停止覆盖，重新读取并合并；无法判断归属则报告冲突，继续不写该文件的工作。
8. 写入后检查实际 diff、文件结构或格式对应的渲染结果，确认路径正确、无越界修改。TRACKED 任务在里程碑检查点记录关键路径和证据，不把完整 diff 复制进状态。
